# Mojibake Fixer

## Overview

修复因字符编码错配（UTF-8 ↔ GBK/GB18030）导致的中文乱码文件。核心脚本是 `scripts/fix_mojibake.py`，纯 Python 标准库实现，无需安装依赖。

## 何时使用

- 日志中出现 `绛惧悕`、`鍙傛暟`、`鎴愬姛`、`锛�` 等典型 UTF-8-as-GBK 乱码
- 用户反馈"日志乱码"、"中文显示为繁体/生僻字"、"UTF-8 和 GBK 转换问题"
- 文件中含大量 U+FFFD（�）或私用区字符（U+E000–U+F8FF）

## 使用方法

运行修复脚本（默认按 utf8-as-gbk 方向修复）：

```bash
python scripts/fix_mojibake.py <输入文件> [-o 输出文件] [--direction utf8-as-gbk|gbk-as-utf8] [--in-place]
```

- 不带 `-o` 时输出到 `<输入>.fixed.<后缀>`，不改动原文件
- `--in-place` 直接覆盖原文件
- `--direction gbk-as-utf8` 用于反向场景（GBK 文本被按 UTF-8 解码）

脚本逐行检测乱码，只修复判定为乱码的行，正常行（含已是正确中文的行）原样保留；结束后打印行统计。

## 工作原理

1. **成因判定**：UTF-8 字节流被按 GBK/GB18030 解码后又保存为 UTF-8，汉字变成生僻字对（如 "签名"→"绛惧悕"）。修复即逆运算：`乱码.encode('gb18030').decode('utf-8')`。
2. **逐行检测**：通过乱码标志字符、U+FFFD、私用区字符判断一行是否需要修复，避免误伤正常内容。
3. **U+FFFD 丢失字节推断**：Java/.NET 解码器遇到非法字节会输出 U+FFFD 并丢弃原字节（信息不可逆丢失）。脚本将每个 U+FFFD 视为"未知的 1 字节"，利用 UTF-8 编码结构约束枚举候选字节，用动态规划按以下启发式选最优：
   - 内置汉字频率表（常见字优先）
   - 文档自身上下文的单字/二元组频率（两遍扫描，同一文件用词一致）
   - 内置日志/技术领域常用词二元组（如"运行中"、"审核中"、"所有"）
   - 高频中文标点优先（如 "，" 优先于生僻全角符号）

## 注意事项

- 含 U+FFFD 的行属于有损修复，个别字符可能猜错（脚本统计中显示为"含丢失字节(已推断)"）；相邻 2 个以上连续丢失字节无法推断，保留 � 标记
- Windows PowerShell 下向 Python 传递含中文/乱码的文件路径可能因 ANSI 代码页出错，可先用 `Copy-Item` 通配符把文件复制为 ASCII 文件名再处理
- 修复结果始终以 UTF-8 写出
